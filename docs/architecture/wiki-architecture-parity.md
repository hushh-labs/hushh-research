# Architecture and shared explanations

[Architecture](README.md) · [Authoring contract](../development/documentation.md)

The repository owns current implementation explanations. Shared Wiki articles
should link to the relevant module rather than copy its runtime inventory.

## Visual Context

The [system diagram](system.md) and [module maps](README.md#modules) own the
architecture. The existing runtime topology generator derives implementation
inventory; a diagram is not proof that a node is enabled or installed.

## Reconcile a shared article

1. Verify the source module and its current versus future boundaries.
2. Update links and statements together; preserve exact operational evidence where needed.
3. Read back a published change only when publication is authorized.
4. Keep private evidence out of public comments and documents.

Do not maintain another layer taxonomy, generated static platform poster or
parallel handbook. Use Git history for previous architecture explanations.
