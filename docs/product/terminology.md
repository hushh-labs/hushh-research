# Product and implementation terminology

[Product](README.md) · [Personal-agent identity](principles/agent-ontology.md)

Use plain language to explain the product. Preserve literal names when someone
must use an API, command, schema or compatibility contract.

| Name | Meaning and current boundary |
| --- | --- |
| Hussh | The platform, trust model and infrastructure. Its architectural expansion is Human Secure Socket Host. |
| One / Agent One | The private agent and root ADK coordinator. It owns the relationship and delegates bounded work. |
| Kai | One’s finance specialist. Existing Kai-named routes, generated action contracts and package symbols remain literal compatibility interfaces. |
| Nav | The bounded privacy and consent specialist. It is not a separate security process that contains arbitrary agent code. |
| KYC | The identity-workflow specialist under One, with its own admitted scopes. |
| Puppy | Owner-approved inference on a trusted computer through a BYOC binding. |
| PKM | Personal Knowledge Model: encrypted personal records plus governed structure, scope and discovery metadata. Current canonical chat memory is Markdown stored within PKM. |
| Scope | A bounded description of information or capability that can be requested and granted. It is not blanket access to memory. |
| PCHP | Personal Consent Handshake Protocol: implemented boundaries are the consent request, approval/status, scoped export and audit contracts. |
| Capability token | A specific authority such as `VAULT_OWNER`, a consent token or developer token. Authentication is not interchangeable with any of them. |
| Bring your own AI | An admitted owner model connection. Supported selection and verified provider authority remain deployment-specific; never infer a fallback. |
| Personal World Model | Product context assembled from selected information and governed memory. Bounded reviewed public research exists behind its own gate; a continuously complete model is not a current guarantee. |

Independent wiki/blob memory, broader autonomous work and new interoperability
patterns stay in the [roadmap](../roadmap/README.md) until implementation and
acceptance establish them. A provider may process information explicitly disclosed
to it; encrypted storage alone does not prove provider blindness.

Use [architecture modules](../architecture/README.md#modules) for technical meaning
and the [brand compatibility contract](../operations/brand-and-compatibility-contract.md)
when changing public names. Do not rename identifiers as a documentation cleanup.
