Conditions: WebKit 2272, 393 × 852 CSS px, nominal 60 Hz, motion enabled,
45 synthetic connected people, three scroll-down/up repetitions, one worker.
Only `scroll:programmatic` windows are summarized. Boot/viewport windows are
excluded. The small sample cannot certify native frame pacing or finger
scrolling; real UIKit composition and software keyboards remain unmeasured.

Reproduce with a locally available baseline commit:

```sh
cd hushh-webapp
SHEETS_BASELINE_REF=bd1a343bfbb8526969093512fa00b98d7c7a6af6 CI=1 ./node_modules/.bin/playwright test e2e/circle-invite-picker.layout.spec.ts --project=webkit --workers=1
```

The opt-in diagnostic test builds the actual previous component, uses
`startFramePacingProbe`, requires real scroll windows, attaches both JSON
snapshots and stops the sampler. The normal layout pack covers optimized
centering (including a negative control), keyboard/safe-top geometry, stable
selection across resize, opaque light/dark canvases, blurred scrims and
constrained confirmation reachability. Native Android keeps its existing
blur-free fallback.
