# Portable PDF artifact generation

This is the platform-neutral behavioral source for Hussh PDF artifacts. Codex and
Claude discover it through thin bridges; edit this file when the shared practice changes.

## Canonical implementation

| Concern | Source of truth |
| --- | --- |
| Tokens | `hushh-webapp/app/globals.css` |
| Formatter profiles and print geometry | `hushh-webapp/lib/morphy-ux/pdf-document-formatter.mjs` |
| Markdown, semantic directives, HTML, and PDF export | `hushh-webapp/scripts/reports/export-markdown-pdf.mjs` |
| Calendar-ready GitHub evidence collection | `skills/pdf-artifact-generation/scripts/collect_github_month.py` |
| Source-linked contributor calendar Markdown | `skills/pdf-artifact-generation/scripts/render_github_month_calendar.py` |
| Codex routing bridge | `.codex/skills/founder-brief-curation/references/pdf-artifact-generation.md` |
| Claude discovery bridge | `.claude/skills/pdf-artifact-generation/SKILL.md` |

Use this path. Do not add an artifact-local stylesheet, font bundle, HTML renderer,
or a second token palette. The portable artifact is a consumer of the app Foundation,
not an independently branded document system.

## Choose a profile before authoring

- `technical`: precise implementation notes and reference material.
- `partner`: concise external technical material.
- `founder`: narrative architecture and founder-facing briefs.
- `executive`: decision-oriented audits or leadership reviews; supports a full-bleed cover.

Use the four published Foundation themes only: `light`, `dark`,
`molten-gold-light`, and `molten-gold`. Never hard-code an accent or approximate a
theme in report Markdown or CSS.

## Author semantic content, not presentation escapes

The renderer accepts Markdown plus narrow semantic directives. Use a directive only when
the information itself has the stated meaning:

```markdown
<!-- pdf:table=metrics -->
<!-- pdf:table=scorecard -->
<!-- pdf:table=evidence -->
<!-- pdf:table=ledger -->
<!-- pdf:profile-start -->
<!-- pdf:profile-end -->
<!-- pdf:table=calendar -->
<!-- pdf:table=calendar-list -->
<!-- pdf:callout=decision -->
<!-- pdf:callout-end -->
<!-- pdf:page-break -->
```

Use fact rails for a small group of key measures; use a ledger or evidence table only for
comparisons and traceability. Do not recreate decorative boxed/zebra dashboards, badge
stacks, or per-report visual grammar. Keep one person’s executive profile together.

`pdf:table=calendar` is a seven-day month grid, not a productivity score. Use weekday
headers and cells in the form `date :: primary event measure :: optional supporting detail`;
use `—` for an intentional blank. For an executive GitHub audit, the detail is a concise,
linked representative PR or issue title; include its head-commit link where available. State the
metric legend and timezone in nearby prose, and label merge/open/issue timestamps as source-event
dates rather than claimed work dates.

`pdf:table=calendar-list` is the executive default for a GitHub work-progress calendar: one
source-linked row per active local date with `Local date | Recorded event | Audited delivery`.
Use it when leadership needs to see what moved, not merely the volume of activity. Account for
the entire month: render every contiguous no-activity interval as a muted dated row rather than
leaving unexplained gaps.

## Executive cover contract

`pdf:cover` is a physical page, not an inset dark card. It is available only with
`--profile executive` and has three non-negotiable rules:

1. It is the first semantic block in the source.
2. It has exactly one start and end directive.
3. It is immediately followed by an explicit page break.

```markdown
<!-- pdf:cover-start -->

Cover thesis, factual metric rail, and decision callout.

<!-- pdf:callout=decision -->
Decision text.
<!-- pdf:callout-end -->

<!-- pdf:cover-end -->
<!-- pdf:page-break -->
```

The shared exporter maps this to the named `pdf-cover` A4 page with `margin: 0`; normal
document pages retain the formatter’s reading margins. Any white perimeter, corner bar,
or visible page background around a cover is a release blocker, not a stylistic choice.
Do not simulate full bleed with negative margins, a fixed overlay, or a separate PDF merge.

## Monthly executive reporting cadence

For a recurring GitHub report, collect a fresh, UTC-bounded evidence file before writing the
artifact. Use the portable collector rather than a copied one-off script:

```bash
python3 skills/pdf-artifact-generation/scripts/collect_github_month.py \
  --org hushh-labs --month YYYY-MM --timezone America/Los_Angeles \
  --person 'Display name=github-login' \
  --output tmp/github-activity-YYYY-MM.json
```

Run the collection only with read-only GitHub access and preserve the resulting JSON beside
the requested artifact. `--timezone` is mandatory: it defines the local calendar, source
window, and every rendered date label; never silently fall back to UTC or the machine timezone.
The collector fails rather than silently truncating a GitHub Search
cohort above the API’s 1,000-result cap. Then follow the focused source and interpretation
rules in [monthly-executive-report-cadence.md](./references/monthly-executive-report-cadence.md).
Never derive hours, compensation, or individual performance from calendar events, commits,
or diff churn; use them to identify delivery and the review/validation surface.

## Render and verify

```bash
cd hushh-webapp
node scripts/reports/export-markdown-pdf.mjs \
  --input <artifact.md> --output <artifact.pdf> --html <artifact.html> \
  --theme light --profile executive
```

Before sharing, inspect rendered pages—not just Markdown or HTML—for:

1. physical page 1 corners matching the cover ground with no white perimeter;
2. page 2 and later retaining readable margins;
3. no clipped type, table overflow, orphaned profiles, or accidental empty pages;
4. hierarchy that moves from thesis to evidence to individual attention to sources;
5. embedded Inter body typography and Foundation-derived colors in the chosen theme;
6. source links that are shareable rather than machine-local paths.

For monthly reports, also verify that the calendar has every day in the declared UTC month,
uses only collected event types, includes its legend, and does not split across pages.

Run `python3 scripts/ops/verify_pdf_artifact_contract.py` whenever changing the common
artifact path or a cross-platform bridge. Render at least one representative executive
fixture after geometry changes and retain only the requested artifact outputs.

## Cross-platform maintenance

The root `skills/` file is the only portable behavior contract. A Codex bridge may preserve
governed routing metadata, and a Claude bridge may preserve discovery frontmatter, but
neither may restate this procedure. The historical `morphy-pdf` Claude skill is a
compatibility alias only and must never regain a private renderer or stylesheet.
