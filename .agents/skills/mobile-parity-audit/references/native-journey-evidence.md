# Native Journey Evidence

Use this protocol when qualifying an iOS route or nested component journey. It keeps source, runtime, visual and build evidence tied to the same candidate.

## Before interaction

- Bind the run to the app and test-runner build identities, target device, route, and exact test. Keep install, test-body entry, interaction, visual/accessibility review, and release-performance evidence separate.
- Preserve normal project signing for simulator apps that use Firebase or Keychain. `CODE_SIGNING_ALLOWED=NO` can remove the simulated entitlement sections and break authentication. Inspect the executable's `__TEXT,__entitlements` section and expanded keychain groups; an empty `codesign` entitlement report alone is not authoritative for a simulator. Reuse unchanged exported assets for a signing-only correction.
- Compare test-body duration with elapsed run time before blaming UI complexity. If `pmset` confirms maintenance sleep on AC, use a bounded, task-owned `caffeinate -is` process and confirm `PreventSystemSleep=1`; an idle-only assertion can be insufficient. Stop it at handoff; do not change global power settings.
- Read the current route and component source before choosing controls. Use a unique, source-backed locator; do not guess by array index or label alone. Root chrome titles may be static text rather than a navigation bar; use the bounded canonical route status and the observed content owner instead of requiring the wrong UIKit container.
- Confirm the starting screen and its privacy/session gates. Before tapping, confirm the scoped control is unique, enabled and reachable. On failure, record count, existence, enabled state, hittability and bounds separately; successful actions do not need a full diagnostic packet each.
- Define the bounded journey, expected renderer and legitimate populated/empty/unavailable terminal states before tapping. A parent/menu receipt does not prove every child or sibling branch. A control has one presentation owner for its lifetime. Native eligibility does not recursively convert descendants: qualify parent → child → menu/editor → dismissal → return. Ordinary controls must stay in the admitted native composition; name genuine map/provider/chat handoffs and preserve their complete visuals.
- For the Experimental native-interface preference, verify both directions through the real Profile pane: save keeps the current renderer; a full process restart applies the saved choice. The supported-wrapper opt-in affordance must remain available while native rendering is Off. Qualification flags do not substitute for this user choice; legacy full-page Profile routes are not proof of the native pane.
- Treat WebView accessibility as phase-specific: a native owner may intentionally hide its AX tree. Require a WebView only after returning to a Web-owned phase, and include a source-backed recovery path for every starting state the runner explicitly supports.
- Scope controls to their owning form or presentation. For offscreen form actions, scroll the identified form table/scroll view; avoid a global generic-label count. Record locator/admission failures separately from post-tap transition failures, and try the form's authored Cancel before route-level dismissal.
- Re-read bounds after scrolling and require a stable target before tapping; an interaction that only stops scrolling is not a selected row. WebView controls and native collection cells can report hittable beneath the dock or system glass toolbar. Require the entire target to clear the observed toolbar material, header, navigation and keyboard bounds. When tabs hide on scroll, use the existing `native-workspace-scroll` viewport as the native content bound; an approximate screen/dock rectangle can put an offscreen target on the wrong side of the scroll calculation. Use the actual window width; an invented horizontal inset can incorrectly reject a valid full-width row. Exclude shell actions from recursive feature locators.
- Assert the visible destination and usable content after a transition. Do not use a generated row ID as proof of restoration across a remount; identify an authored destination and scope repeated labels to the intended detail or navigation owner.
- Scope same-named shell breadcrumbs and content Back controls separately. Check the route graph and the running shell before adding another Back control; nested states use the existing Back layer when the shell already owns Back. Resolve Back from the actual entry context. Direct entry may have a different authored parent from dashboard entry. UIKit can expose the previous page title as its Back label even with a compact visual button; scope the locator to the observed navigation bar and supported parent label. Reopening a pane may restore its retained child directly instead of its menu.
- Coherent native shells can retain chrome without advertising the legacy reserved-region capability. Intentional React sheets/dialogs must consume the existing workspace seat and mirrored shell geometry, including keyboard clearance. Verify the actual footer/last row against the dock and compare optimized CSS with the renderer-off case; a passing tap test alone does not establish visual clearance.
- After runner edits, require the expected in-body checkpoints. Matching installed bundle hashes alone do not prove the running test code is current. If logs still execute removed steps, terminate/reinstall only the task-owned runner before retrying; preserve the app-under-test and its account. Forward XCTest runtime parameters with the supported `TEST_RUNNER_` prefix and confirm the resumed in-body checkpoint; the host shell environment alone is not proof of delivery.
- Reuse unchanged journey evidence. Select the smallest existing regression checks and one connected visual session for the changed behavior; do not create a permanent runner or repeat an accepted path solely to refresh a receipt.
- Verify repeated native → React → native visits in the same session. The incoming React plane can prepare behind its native parent while touch/accessibility remain isolated. A retired React plane must not wait for the restored native parent to disappear before admitting the next visit. Keep pane retirement separate from native-parent ownership; mount nested React confirmations through the existing admitted overlay port.
- Text entry may replace a selection, and validation may reject an overlength draft. Use a valid reversible edit and authored Cancel/reopen to prove draft discard rather than assuming typing followed by backspace restores the original. Wait for a read/refresh to settle before requiring navigation controls in accessibility.

## Compile-only UI-test harness checks

- When source changes need compiler validation but the app-under-test must not be built or run, use a private copy of the runner project with no App/AUT target dependency and include every `AppUITests` source required by the target. Use `build-for-testing` only, then inspect the generated `.xctestrun` to confirm it has no AUT path and references only the test runner. This proves compilation, not test execution or app behavior.
- Remove the copied project and DerivedData after the receipt is captured. Preserve only a bounded, sanitized build receipt and log.

## Simulator GUI and keyboard

- In Xcode 27, use [Device Hub](https://developer.apple.com/documentation/xcode/device-hub) for visible simulator interaction. Keep `simctl` state checks separate from visual UI evidence.
- For keyboard issues, inspect Device Hub's visible keyboard controls and verify the software keyboard's onscreen frame and inset before text entry. Apple lists “Toggle Software Keyboard” as not working for iPad simulators running iOS 27.0 in the [Xcode 27 release notes](https://developer.apple.com/documentation/Xcode-Release-Notes/xcode-27-release-notes). Never bypass an offscreen-keyboard gate.
- When opening Device Hub in the background, verify the host app remains frontmost; a background-open flag alone is not proof. Restore prior focus if the launch changes it.
- Device Hub can expose a disabled keyboard menu until its device view is selected. Inspect the actual `Simulate Hardware Keyboard` menu checkmark; the old Simulator preference alone does not establish its state. If the owner permits a brief focus change, select the device view, disable hardware simulation, restore prior focus, and verify onscreen keyboard geometry before entry. Do not retry typing against an offscreen keyboard.

## Fit and visual review

- Inspect every root pane and connected dialog in its authored presentation before freezing the native candidate, including action hierarchy, density and tap bounds. Compare Standard and Native on the same device type, runtime, artifact, appearance and authorized account state. Check graphics, imagery, chart context, table columns/sort/paging, inline actions and information hierarchy; do not count text summaries or an extra drilldown as equivalent presentation. Record fixture differences. Preserve the complete rich presentation at its original level until its native mapping is complete; do not remove graphics to obtain a native claim. Paired captures are visual evidence, distinct from action/binding checks.

- Review actual device frames after each meaningful transition. Markup, source geometry, and a successful build do not prove rendered fit.
- Keep full-height feature panes outside centered-dialog geometry rules. Inspect the optimized selector and measured pane/header rectangles; a working Back tap alone does not prove layout. Apply the shared layout correction rather than adding a second feature geometry owner.
- Check text and control frames for clipping, wrapping, overlap, duplicate controls, stable reserved space, and active-pane ownership. Native button styles add their own padding: measure the final target, avoid stacking a large label minimum with large control padding, and preserve the authored primary/secondary hierarchy and compact person actions. Check touch and accessibility results separately.
- Attach native feedback to the currently visible UIKit page so its safe area includes navigation controls. Resolve rasterized menu-image colors against the committed appearance traits; ambient traits may still belong to the previous theme.
- Read each native editor's UIKit type before selecting an XCTest query. A single-line SwiftUI input may wrap `UITextView`; its custom Clear button may be a sibling rather than a text-field child. For Form switches, verify the observed value changes; a label-centred tap may miss the trailing thumb. Reject a passing runner with missing journey checkpoints.
- During sheet retirement, reject reentrant refresh before reading the host being released. SwiftUI view destruction can synchronously withdraw menus and call back into that owner; retain the existing retirement boundary rather than scheduling another lifecycle.
- Treat UIKit/SwiftUI surfaces as separate from the WebView stacking context: DOM `z-index` cannot lift a Sonner toast above them. Use the existing native feedback adapter and one renderer owner.
- In admitted native mode, use the existing SwiftUI feedback presenter. Sonner may own records/promises, but ordinary notices must not block navigation, retire a workspace, or mount a competing DOM banner. Map bounded text, tone, duration and authored action handles explicitly; decorative icons use native equivalents. Verify updates and terminal callbacks settle once, and owner/privacy changes reject late results. Unsupported custom content requires an explicit feature mapping; do not interpret arbitrary JSX.
- Keep native admission, retirement and reactivation in the shared workspace boundary. Allocate one identity per presentation lifetime; delayed retirement may release only that identity. Require confirmed absence before exposing Web fallback. Owned sheets temporarily cover their parent; coverage is separate from renderer failure. Verify both retained-route reentry and unmount/remount.
- Preserve authored primary taps, independent secondary actions and phone-specific action substitution. Do not merge desktop and phone action bundles or turn an inert status into a navigation control. Expanded children retain their parent and Back follows only visible local state.
- Bound the complete escaped UTF-8 bridge envelope, including imagery and text, before transport; individually bounded images do not establish a bounded message. Keep JavaScript and Swift closed shapes aligned, including explicit-null rejection. Oversized unsupported content retains its complete authored presentation rather than truncated information or actions.
- An awaited native-to-React handoff must resolve the current feature action again after retirement, including enabled/pending state and owner identity. A row eligible at tap time may become invalid while its reader refreshes. Guard consequential entry against current evidence (for example complete Calendar coverage and the selected opening); keep this check in the existing owner, not a second cache or lifecycle. Prove the stale-action rejection with a focused negative control.
- Remeasure an authored chrome seat immediately before bridge apply after asynchronous admission. Concealing its React replica or restoring navigation can move an unchanged-size seat; ResizeObserver alone does not prove current coordinates. Keep owner/generation fences and reject detached or invalid seats. A synthetic resize is diagnostic evidence, never runtime acceptance.
- Feed existing shell measurements and native keyboard transitions into the shared presentation-region boundary. Route seats must preserve their acknowledged chrome bounds while a child covers them. Native scroll/focus remains local. Review actual light/dark canvas and bottom clearance before accepting the route.
- Separate an admitted sheet's attached lifetime from its pending content layout. A routine draft acknowledgement may require a new layout receipt, but must not revoke ongoing editor input; otherwise a keystroke during that gap can clear the editor and incorrectly trigger full React fallback. Opening and retirement still reject input, and new presentation receipts still wait for settled layout.
- Pair an accepted edit revision with its accepted draft while React commits asynchronously. Keep the feature’s logical draft in its existing React owner so native and complete fallback share it. Fence final edits by the form visit; a cancelled or newer visit must reject old edits. Never acknowledge new input using the previous render's text. Keep this transient replica in the shared adapter, discard it on retirement, and let a newer authored revision supersede it. Pin editor Save/Cancel in native chrome when long forms and the keyboard would bury them; observe the editor's immediate pending/composition state there too.
- If an operation can outlive its child sheet, scope its outcome to the parent workspace. Confirm it publishes once after sheet retirement, with no duplicate DOM toast or stale replay.
- Verify static empty-state text by its visible frame and bounds; reserve hittability checks for actionable controls.
- Resolve native-versus-Web locators after transition admission, inside the wait predicate. A one-time fallback choice can keep waiting for the wrong renderer. Use authored identifiers for shared chrome; an offscreen virtualized row is not evidence of a different action or state. Restore/reveal the list position with bounded scrolling, and capture failure diagnostics before teardown changes the screen. Resume at the remaining journey once unchanged earlier slices are accepted.
- Recheck the focused editor's bounds after the software keyboard appears. A successful edit and reachable Save do not prove the editor is visible. Ordinary sheets use their existing UIKit owner and `keyboardLayoutGuide` to bound the SwiftUI form viewport; do not add a competing JavaScript keyboard measurement or a notification observer per field.
- For text entry, record field focus, keyboard count and onscreen frame, available inset, recovery reachability, and overlay isolation. Accessibility focus alone does not prove that the keyboard can accept input. If keyboard geometry does not intersect the app window, do not type; record bounded window, keyboard, intersection, and inset measurements, continue only unaffected read-only route checks, and mark input unqualified.
- Cover the connected path: select, reselect, dismiss, retain draft, Cancel, and authored return. Capture the resulting states, not only settled entry screens.
- After tab reentry, inspect the insertion point before deleting synthetic text. Verify a changed value or dirty Save state after typing, then use authored Cancel for private editors; typing alone does not prove that the model accepted input.

## Failure and retry

- Persist a bounded structured receipt with stage, guard values, exact device and build identity, test result, build count, retry cause, stage duration, and private capture manifest. Console output is supplemental; essential failure evidence must survive in the receipt.
- Classify failures as product, harness, simulator/environment, or fixture before changing code or retrying. A retry needs new evidence and a specific correction; stop repeating the same unsuccessful approach after two attempts.
- Review captures before changing product code to satisfy a conflicting accessibility assertion. Preserve both outcomes and their limitations.
- Keep owner screenshots and receipts in ignored private storage. Persist the sanitized receipt and capture hashes successfully before deleting private evidence. After visual review, remove only the exact temporary captures created for that review and verify their removal.

- Fixed feedback controls are not scroll targets. When their observed frame is onscreen but strict hittability fails, stop scrolling, preserve the independent AX/touch outcomes and inspect the owner’s hit region. Prove dismissal before the notice’s authored expiry; eventual disappearance alone may be timer expiry.

- Validate a feature projection against the specific workspace validator before freezing. `NativeDrawerRow` also describes Profile controls that the workspace does not render or admit; its TypeScript shape alone is insufficient. Use supported workspace rows or an existing complete presentation, rather than silently introducing a Profile menu payload.
- A child native workspace needs the complete route-body seat. Put the React tab strip and supporting controls inside its complete fallback; do not retain them as accessible siblings under an opaque native host. Verify the native tab has one accessibility match on selection and reselection. Programmatic pager settlement acknowledges the tab owner's selection; it must not emit a second navigation. This is a layout composition correction, not a reason to add another lifecycle or isolation map.
- Root tabs keep one presentation across their family. If a native body cannot preserve a rich pane, retain the complete family presentation instead of switching the tab strip's renderer, position and size between panes. Native conversion remains open; a working callback does not qualify the flattened layout.

- On a cold simulator launch, confirm normal native shell/composer readiness before debugger-assisted warm navigation. Pausing the app while its read-only capability lookup is pending can expire the JavaScript deadline and cache an unavailable result for that document. Separate that instrumented session from a normal-launch continuity check before changing product code.
- Register feature Back layers against normalized static-export paths. Resolve Back through the shared destination-origin owner, not only a route's static breadcrumb parent. A warm journey launched from Chat can correctly return to Chat. Warm-session launch-marker fields may still describe the original audit target; record conflicting predicates and verify the actual route, native destination and reviewed capture rather than changing navigation or claiming a cold inventory pass.

- Resolve authored CSS variables through existing theme utilities before sending bounded native colors. Testing one literal-color fixture does not validate token-backed palette entries. Read the actual accessibility tree before choosing element type: a labeled SwiftUI container may expose its Button as a descendant. Preserve strict AX failures separately from bounded touch success.

- Keep effect-only business components mounted across renderer selection. In retained multi-pane routes, admit only the selected pane; explicitly exclude secondary/history readers from native collection admission. Derive activation from the route and selected surface, rather than a parent mount ref evaluated during the child’s first render. A retained pane's menu must retire when that pane becomes inactive; an admission cancelled before a native lifetime exists must release its pending attempt. Confirm retirement before replaying its original open intent through a complete fallback after genuine admission failure.

- A retained control can move without changing its own size when surrounding navigation is removed. Observe the existing enclosing shell as well as the control; verify actual native-frame clearance during that transition rather than adding feature padding or replacing the retained host.

- UIKit's full-viewport `PopoverDismissRegion` is not a safe geometric tap target: its center can activate a presenting control. Use an observed non-interactive point outside the popover, then confirm both dismissal and the retained route before further input. Dynamic openings need a live semantic locator rather than a captured private row ID that expires on refresh.
- Immediate choices anchor to their measured trigger. Install the adaptive presentation delegate before UIKit begins presentation, and verify actual compact-phone bounds; setting `.popover` alone does not prove that UIKit avoided sheet adaptation. Preserve strict accessibility-frame failures separately from source-measured touch results.
- Center intentional React dialogs within the existing acknowledged native region. If its bottom already includes keyboard clearance, do not apply the generic keyboard lift again. Measure actual dialog/title/control bounds and horizontal overflow; implicit grid tracks and a native select's long option can overflow even when the outer form width fits.
- A full-screen Profile presentation covers the workspace's dock and navigation. Its nested sheets clear the keyboard rather than the covered shell. Verify both the open-parent bounds and restoration of the normal workspace reservation after that parent closes, using optimized CSS and the running artifact.
- A new logical native page must start with its own presentation/scroll identity while the feature's reader and draft owner stay mounted. Use the existing React/shared workspace lifetime boundary; changing projection content alone must not carry an unrelated page's scroll offset.

- Verify positional control contracts against the actual renderer, not labels alone. The existing Swift toggle reads and dispatches option 0 as On and option 1 as Off. A model emitting Off first reverses both presentation and the writer argument even if a test finds the correct callback by its label. Exercise both positional directions and retain the retired-owner negative control.

- Route-local presentation ownership does not fence a different route. Await the existing cross-route workspace retirement barrier before incoming admission; preserve an unresolved predecessor fence. Keep failure diagnostics bounded to a workspace name and known error code, never scene values.
- Treat an authored DOM dialog as temporary coverage through its existing overlay token, including exit motion. Retire native controls before React exposure and readmit after token release; do not latch a renderer failure. A native toggle that opens an authored React grant-scope review must retire before that callback; an admitted native review retains its parent workspace. An enabled rule must retain an explicit scope-review action.

- Native chrome capability discovery and native identity admission must use the same closed control vocabulary. For dock fitting, observe the actual active surface as well as its enclosing shell: intrinsic field/placeholder sizing can move it without changing the parent box. Reattach that observation after hidden-route reentry. Suspension may retain an editor and draft while concealing its host; hidden-route paint and active-route placement need separate visual checks.

- Count initials-only portraits against bridge media limits too. Bound the displayed native page to the existing schema and preserve access to every loaded record and its callbacks. Reset a new page through the existing scroll owner; anchor the content itself rather than adding a spaced child.
- Keyboard clearance can advance a presentation revision while a confirmed dismissal is awaiting JavaScript. Preserve nondestructive cancellation only for its exact active editor/pending intent; retain owner, privacy, busy and successor fences, and keep Save’s stricter draft checks. Review moving panes with opaque canvases so outgoing content does not ghost through an incoming screen.
- Foreground activation does not prove resume animations have settled. Wait for the current authored surface before the next action, and resolve shell identifiers from the source registry or observed tree. Back may first unwind a selected nested step; verify that state before expecting the route parent.

- When leaving an open-ended duration for Custom, commit the concrete timed value shown before allowing submission. Preserve final committed input separately from active action eligibility; fence it to its original owner/visit so it cannot overwrite a reopened successor. When formatting inserts separators, preserve the caret’s semantic character position and verify continuous typing; case-only normalization checks do not establish this.
